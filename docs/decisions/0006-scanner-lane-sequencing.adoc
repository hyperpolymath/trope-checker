== Context — how the governance lane vanished silently

This repo adopted the estate fork-governance lane (DEED syntax, K9-DEED
conformance grid, gitbot-fleet report-backs, Hypatia verdict grid, one PR
comment) on 2026-10-28, yet no grid or assessment ever appeared on PR #107.
Root cause, in two layers:

. *The repository had never opted in.* Before `fork-governance.yml` existed
  here there was no fleet enrolment and the Hypatia caller rendered its grid
  into an artifact nobody downloaded.
. *Then the lane's coordinates died.* `standards` was transferred from the
  `hyperpolymath` user account to the `metadatastician` organisation on
  2026-10-25 (repository id 1116521501, history preserved). GitHub redirects
  git clones, web links and REST API calls for the old name — but *not* a
  reusable workflow's `uses:`. Every standards reusable called from this
  repo (fork-governance ×4, governance, hypatia-scan, secret-scanner,
  scorecard, mirror) therefore failed at startup with "workflow was not
  found", created *zero jobs*, emitted *no check run*, and posted *no
  comment*. `gh pr checks` showed a clean-looking list in which three
  workflows were simply absent.

Two defences nearly caught this and didn't:

* This repo's `workflow-linter.yml` re-resolves every external pin — via the
  redirect-following REST API, which cheerfully resolves commits under a
  moved name. Resolution ≠ canonicality.
* Hypatia-current detects the exact class (rule WF028,
  `reusable_call_to_moved_repository`), but the estate's pinned scanner
  (standards default `aa34a4c…`) predates WF028 by 135 commits, and WF028 is
  advisory/low severity, below the scanner's default reporting threshold.

A second, independent defect compounded the first: the local
`static-analysis-gate.yml` ran duplicate Hypatia and panic-attack jobs at
*divergent pins* with incompatible semantics (header said "advisory, cannot
fail"; two jobs could in fact fail on criticals; `ci/CI-CRITICALITY.toml`
listed it as a merge gate). Its Patch Bridge job had never once executed the
tool: it passed a non-existent `--format json` flag against a directory
with no supported lockfile and then *replaced the error output with a
fabricated all-zero report*. A green check asserted CVE evidence that did
not exist.

== Decision — the canonical sequence

Per pull request, evidence flows in one acyclic sequence. Each stage has
exactly one owner; nothing downstream re-derives what an upstream stage
owns.

[cols="1,3,3",options="header"]
|===
| Stage | What runs | Contract

| 0. Coordinate preflight
| `workflow-linter.yml` resolver
| Deterministic and blocking: every external `uses:` pin resolves, the
  repository's canonical `full_name` equals the coordinate as written
  (moved-repo detector), and every reusable workflow path exists at its
  pin. This is the gate WF028 cannot be: Hypatia reports it advisedly,
  the linter refuses it.

| 1. Producers (parallel, read-only, comment-free)
| DEED syntax · K9-DEED conformance · gitbot-fleet report-backs
| Each emits artifacts/envelopes only. Fleet executes enrolled adapters in
  manifest order, so `.gitbot-fleet/enrolment.json` is written in Kin
  Arbiter priority order (echidnabot > rhodibot > panicbot > sustainabot >
  glambot > seambot > finishingbot > cipherbot > accessibilitybot).

| 2. Findings lane (needs: fleet)
| standards `hypatia-scan-reusable.yml`
| Hypatia (the lane's only gating row) + panic-attack assail +
  pons-asinorum (advisory status envelopes) → verdict grid → SARIF upload
  (alert-derived meta-findings excluded at SARIF render, so the upload can
  never echo back as next run's "findings") → blocking decision taken from
  the baseline-filtered SARIF, not from raw JSON.

| 3. Publication
| standards `fork-governance-reusable.yml`
| Exactly one PR comment, marker-identified, updated in place: summary
  table, K9 grid, Hypatia grid. Lanes never post themselves; a lane that
  produced nothing renders orange ("indeterminate"), never absence.

| 4. Disjoint CVE surface
| `patch-bridge.yml` (panic-attack Patch Bridge)
| Lockfile CVE triage only. Applicability is computed and recorded as an
  envelope: with zero supported external dependencies the result is
  `not_applicable` — a statement about the tool's surface, never a clean
  bill. Tool failure or malformed output fails the check; findings are
  advisory.

| 5. Push / schedule
| `hypatia-scan.yml`, `secret-scanner.yml`, `scorecard.yml`
| The same reusable and the same scanner pins as stage 2 (baseline/SARIF
  reconciliation on main). `secret-scanner` carries this repo's one
  ruleset-required status context, `scan / gitleaks` (ruleset
  Secret-Scan-Floor; the only other active branch rule is
  Require-Signed-Commits) — its caller job key must not be renamed.
|===

== Clash-resolution rules

. *One scanner, one version, per trigger class.* Hypatia `adb2f41…` in
  every caller (the standards default predates WF028); panic-attack at the
  standards pin `b689a74…`; pons at the standards pin. Divergent local
  builds are not defence in depth; they are two truths.
. *One producer per finding family.* Fleet enrolment declines, with
  reasons: `panicbot` (panic-attack already has a direct grid row —
  enrolling it double-counts), `echidnabot` (proofs are gated by their own
  toolchains in `proofs.yml`; no ECHIDNA engine is configured, so the
  adapter could only report `not_run` forever), `cipherbot` (no
  cryptography is implemented here; the hashes present are integrity pins),
  plus the pre-existing `seambot`/`accessibilitybot`/`sustainabot`
  declines. Grey rows with reasons beat orange rows without evidence.
  Active reporters — rhodibot, glambot, finishingbot — carry explicit
  `"gating": false`.
. *Gating precedence is singular.* Of the grid rows only Hypatia gates;
  the lane state is its worst gating row under
  purple > red > orange > yellow > blue > green, with grey reserved for
  declared non-applicability. Missing or malformed evidence is orange,
  never green and never an empty findings file.
. *No presence proxies.* A step that cannot run its tool must say
  `not_run`; it must never print a pass. (The cicd-suite
  `custom-tools-check` composite did exactly that for panic-attack/pons in
  `main-estate-audit.yml`; the step is removed — see upstream prompt.)
. *Neural/heuristic layers advise; they do not adjudicate.* Hypatia's
  neural apparatus may demote or route findings (novelty forces
  `report_only`) but never creates, promotes or blocks on its own output.
  Deterministic direct evidence outranks external-alert-derived evidence,
  which outranks heuristic/neural confidence.
. *Preflight headers are not conformance.* `dogfood-gate.yml`'s DEED/K9
  jobs are fast header-level preflights; fork-governance is authoritative
  on semantics. The scheduled `rhodibot.yml` shell audit is a drift
  reminder, not Rhodibot evidence — the fleet adapter's report-back is.

== Consequences

* PRs get the K9-DEED grid, the Hypatia verdict grid (Hypatia, panic-attack,
  pons, three fleet rows, five reasoned grey rows) and the single
  fork-governance comment — provided this repo's Actions allow-list admits
  the new cross-owner coordinate (see prompt S1; `hyperpolymath/hypatia`'s
  2026-10-27 runs show the refusal where it does not).
* `static-analysis-gate.yml` is retired; `patch-bridge.yml` keeps its one
  honest job. `ci/CI-CRITICALITY.toml` no longer calls the retired
  workflow a merge gate.
* Cross-owner reusable calls are now a *sequenced* dependency: allow-list
  first, canary second, propagation third. Any future repository transfer
  must land in the workflow-linter's canonical-name assertion as a failing
  check with the new owner named, not as a silent zero-job run.

== Canary results (2026-10-28, PR #107 at `60e1600`)

Measured, not predicted:

* 28 check runs success, 1 neutral, 1 skipped, *zero failed*. The new
  `patch-bridge.yml` runs and uploads its `not_applicable` envelope;
  workflow-linter (canonical-name resolver + actionlint + zizmor) and the
  quality regression harness (incl. the new moved-repository fixture) pass.
* Exactly three workflow runs still `startup_failure` — fork-governance,
  governance, secret-scan — each annotated: the canonical
  `metadatastician/standards` reusables "are not allowed in
  hyperpolymath/trope-checker" under the selected-actions policy. No other
  cause remains. The one owner action that completes the repair:
  Settings → Actions → General → "Allow select actions and reusable
  workflows" → add `metadatastician/standards/.github/workflows/*@*`
  (see prompt S1 for the estate-wide version). Note the secret-scan lane
  carries the ruleset-required `scan / gitleaks` context, so main cannot
  go green until this lands. The fallback, if the allow-list must not
  widen, is the fork-local reusable pattern (MetaManifold-WebUI) — viable
  but deliberately not taken here: it vendors ~1,400 lines of upstream
  YAML per repo to work around one settings pattern.
* Two canary defects were found and fixed in the same sweep: a missing
  `actions.lock` entry makes GitHub's dependency locking refuse a new
  workflow's actions at startup (allowlist-worded error), and the
  resolver's canonical query needed the regression harness's `gh` stub to
  answer canonical-name lookups (now a permanent fixture case).
