= Formal Verification Proofs

This directory contains formal proofs organised by proof assistant. There are four
proof developments, each in the role ADR 0005 D4 gives it (as amended 2026-11-17,
`docs/decisions/0005-v0.2-consolidation-o5-and-prover-roles.adoc`):

[cols="1,3"]
|===
| Development | Role

| Agda | The normative kernel: Theorem B and every theory obligation.
| Rocq | A PROOF-POLICY §2 recheck leg, with no `Require`.
| Lean, core | A §2 recheck leg, with no `import` (no Mathlib).
| Lean + Mathlib | A generator, never a leg. Its results become gradeable only once restated in core Agda.
| Idris2 | The executable reference. PROOF-POLICY §8.1 keeps it off the PWG ladder.
|===

== Verification Commands

[source,bash]
----
just proof-check-all       # Run all proof checkers (package builds, both recheck legs + controls, dangerous-pattern scan)
just proof-check-agda      # Agda only (the normative kernel)
just proof-check-rocq      # Rocq recheck leg only
just proof-check-lean-core # core-Lean recheck leg only
just proof-check-recheck-controls  # the planted defects each recheck-leg gate must catch
just recheck-legs          # the three above (mirrors the proofs.yml recheck-legs job)
just proof-check-lean4     # Lean + Mathlib generator only
just proof-check-idris2    # Idris2 only (the reference)
just proof-status          # the four developments by role, then the PWG census

# The two pinned developments need a real build (lake+Mathlib / an All.agda entry),
# not a bare per-file check — proof-check-{idris2,lean4,agda} now do exactly that
# (the ABI seam's abi.ipkg, at the repo root over src/interface/Abi, is checked
# by proof-check-idris2 too). The recheck legs run scripts/check-recheck-legs.sh,
# which fails on a missing or wrong-version prover; it never skips.
# The fuller merges-gate equivalents:
just verify-all            # Lean + Mathlib + Theorem B (Agda) + both recheck legs: build + honesty gate + PWG record
just build-lean            # both Lean + Mathlib harnesses (grade-boundary + grade-factorisation) + axiom audits
just build-agda            # Agda Theorem B (--safe --without-K --cubical-compatible --exact-split -W error)
# the probe also has its own subproject harness:
( cd lean4/grade-factorisation && just falsify )   # sorry-free, axiom-clean, falsifier witnesses live
----

== Banned Patterns

The following MUST NOT appear in any proof file:

- `believe_me` (Idris2)
- `assert_total` (Idris2)
- `postulate` (Idris2/Agda)
- `sorry` (Lean4)
- `Admitted` (Coq)
- `unsafeCoerce` (Haskell)

These are banned as *real constructs*, not as words: the authoritative guarantees are
the provers themselves (`agda --safe` rejects postulates/`trustMe`/`TERMINATING`; the
Lean axiom audit rejects `sorryAx`), which cannot be evaded by comment tricks. The
`just proof-scan-dangerous` lint is a *comment-aware* pre-filter (it strips comments
before matching, so honest prose like "sorry-free" / "no postulate" is not flagged) and
is a pre-filter. CI enforcement is the provers themselves, at full strictness
(`.github/workflows/proofs.yml`, `trope-check.yml`): kernel builds with
warnings as errors, leanchecker re-checking the compiled Lean environment, an
axiom allowlist audit over every Lean module, Agda under `--safe --without-K
--cubical-compatible --exact-split --warning=error`, Idris2 package typechecks
under `%default total`, the two recheck legs under
`scripts/check-recheck-legs.sh` (Rocq `Print Assumptions` and core-Lean
`collectAxioms` on every declared theorem, with no axiom allowed, and six planted
controls that must each be caught), plus the comment-aware source gates in the
same workflows.

== Adding New Proofs

1. Choose the appropriate prover by its role above (and see `../../docs/status/PROOF-NEEDS.adoc`)
2. Create the `.agda`/`.v`/`.lean`/`.idr` file in the right directory
3. Ensure `%default total` (Idris2) or equivalent
4. Run the verification command
5. Update `../../docs/status/PROOF-STATUS.adoc`
